# trans-genderian-orchestra Configuration Skill

You help users configure, customize, and safely improve their TGO setup.

The goal is not just to answer configuration questions. When useful, help the user make their agent system better for future runs: tune models, adjust agent prompts, add focused custom agents, enable or restrict tools, and document restart requirements.

## When To Use

Use this skill when the user asks about or is likely to benefit from changes to:

- `~/.config/opencode/trans-genderian-orchestra.json` or `.jsonc`;
- `<project>/.opencode/trans-genderian-orchestra.json` or `.jsonc`;
- `.opencode/` or `~/.config/opencode/` plugin/agent configuration;
- agent models, variants, presets, or provider routing;
- Conductor delegation behavior or specialist-agent prompts;
- custom agents under `agents.<name>`;
- custom agent `prompt` and `conductorPrompt` blocks;
- skills, MCP permissions, tool access, or disabled agents;
- background orchestration, session reuse, multiplexer panes, `/preset`, `/interview`, or `/deepwork`;
- recurring workflow friction that could be fixed by a prompt/config change.

Also use it proactively, with restraint, when a session reveals a repeatable improvement opportunity. Example: if the user repeatedly asks the same agent to follow a project-specific rule, suggest adding that rule to a prompt or config.

## Current Public Role Names

Use current TGO role names in new config and explanations:

| Role | Purpose |
|---|---|
| `conductor` | User-facing technical lead, planner, router, and result synthesizer. |
| `scribe` | Read-only codebase/docs/source research and uncertainty reporting. |
| `composer` | Scoped implementation, tests, UI/UX, docs edits, and validation. |
| `principal` | Strategic advice and final verification gate. |
| `ensemble` | Multi-model consensus and review panel. |
| `councillor` | Hidden internal Ensemble participant. |

Avoid introducing obsolete role names in new user-facing configuration. If you are helping migrate an old config, translate old intent into the current role names before writing changes.

## What Is Possible

TGO is configured through a plugin config file, usually:

```text
~/.config/opencode/trans-genderian-orchestra.json
```

or:

```text
~/.config/opencode/trans-genderian-orchestra.jsonc
```

Concrete files agents should know:

| Path | Use |
|---|---|
| `~/.config/opencode/opencode.json` / `.jsonc` | OpenCode core config: plugin registration, default agent, providers, user commands, user MCPs. |
| `~/.config/opencode/trans-genderian-orchestra.jsonc` | TGO plugin config with comments/trailing commas; preferred by the runtime loader when present. |
| `~/.config/opencode/trans-genderian-orchestra.json` | Default TGO plugin config generated by the installer for fresh installs. |
| `<project>/.opencode/trans-genderian-orchestra.jsonc` / `.json` | Project-local TGO overrides checked after user config and merged over it. |
| `~/.config/opencode/trans-genderian-orchestra/{agent}.md` | Full prompt replacement for a built-in or custom agent. |
| `~/.config/opencode/trans-genderian-orchestra/{agent}_append.md` | Append-only prompt tuning for a built-in or custom agent. |
| `~/.config/opencode/trans-genderian-orchestra/{preset}/{agent}.md` | Preset-specific full prompt replacement. |
| `~/.config/opencode/trans-genderian-orchestra/{preset}/{agent}_append.md` | Preset-specific append-only prompt tuning. |
| `~/.config/opencode/skills/<skill-name>/SKILL.md` | Installed skill prompt payload. |

Built-in agent prompt file names are exact current agent names:

- `conductor.md` / `conductor_append.md`
- `scribe.md` / `scribe_append.md`
- `composer.md` / `composer_append.md`
- `principal.md` / `principal_append.md`
- `ensemble.md` / `ensemble_append.md`
- `councillor.md` / `councillor_append.md`

Prefer `{agent}_append.md` for small behavior tuning. Use `{agent}.md` only when the user intentionally wants to replace the bundled prompt entirely.

Prompt override lookup order:

1. If a `preset` is active, check `~/.config/opencode/trans-genderian-orchestra/{preset}/` first.
2. Fall back to `~/.config/opencode/trans-genderian-orchestra/`.
3. Replacement and append files are resolved independently. Replacement files replace the built-in prompt; append files are appended after the selected base prompt.
4. If no prompt files exist, the bundled prompt from the plugin package is used.

Common customizations:

- **Switch presets**: choose which generated or custom preset is active.
- **Tune models**: assign different models/variants per agent.
- **Limit costs**: use cheaper models for read-heavy or low-risk specialists.
- **Improve quality**: use stronger models for `conductor`, `composer`, `principal`, or `ensemble` synthesis.
- **Control skills**: set `skills` per agent with `['*']`, explicit names, or exclusions like `['*', '!codemap']`.
- **Control MCPs**: set `mcps` per agent with the same allow/exclude style.
- **Add custom agents**: define focused specialists under `agents.<name>`.
- **Tune prompts**: override or extend an agent's prompt for local workflow preferences.
- **Guide delegation**: add `conductorPrompt` for custom agents so the Conductor knows when to call them and when not to.
- **Adjust background work**: tune `backgroundJobs`, `multiplexer`, or background subagent environment setup.
- **Adjust review panel behavior**: tune `ensemble` councillor presets, timeouts, retries, or execution mode.

Important schema boundary:

- Built-in agents can set models, variants, skills, MCPs, options, temperature, and display names in config.
- Built-in agent `prompt` and `conductorPrompt` fields are **not** supported in `trans-genderian-orchestra.json[c]`; use markdown prompt override files instead.
- Unknown keys under top-level `agents` are custom agents. Custom agents may use `prompt` and `conductorPrompt` directly in config.

## Config Shapes

### Tune built-in agent model/skills/MCPs

Edit the active preset under `presets.<preset>.<agent>`:

```jsonc
{
  "preset": "quality",
  "presets": {
    "quality": {
      "conductor": {
        "model": "github-copilot/gpt-5.5",
        "variant": "xhigh",
        "skills": ["*"],
        "mcps": ["*", "!context7"]
      },
      "scribe": {
        "model": "opencode-go/mimo-v2.5",
        "variant": "high",
        "skills": [],
        "mcps": ["websearch", "context7", "grep_app"]
      },
      "composer": {
        "model": "github-copilot/gpt-5.5",
        "variant": "xhigh",
        "skills": ["simplify"],
        "mcps": []
      },
      "principal": {
        "model": "github-copilot/claude-opus-4.7",
        "variant": "max",
        "skills": ["simplify"],
        "mcps": []
      },
      "ensemble": {
        "model": "conductor"
      }
    }
  }
}
```

### Add foreground model fallback chains

```jsonc
{
  "fallback": {
    "enabled": true,
    "retry_on_empty": true,
    "chains": {
      "conductor": ["github-copilot/gpt-5.5", "opencode-go/mimo-v2.5-pro"],
      "composer": ["github-copilot/gpt-5.5", "opencode-go/mimo-v2.5"]
    }
  }
}
```

Fallback models must already be available to OpenCode.

### Tune Ensemble councillor seats

```jsonc
{
  "ensemble": {
    "default_preset": "mixed-review",
    "councillor_execution_mode": "parallel",
    "timeout": 180000,
    "councillor_retries": 2,
    "presets": {
      "mixed-review": {
        "first": {
          "model": "github-copilot/gemini-3.5-flash",
          "variant": "high",
          "prompt": "Focus: Correctness & Architecture"
        },
        "second": {
          "model": "opencode-go/deepseek-v4-flash",
          "variant": "max",
          "prompt": "Focus: Edge Cases & Security"
        },
        "third": {
          "model": "github-copilot/claude-opus-4.7",
          "variant": "max",
          "prompt": "Focus: UX & Performance"
        }
      }
    }
  }

```

### Append instructions to a built-in prompt

Create, for example:

```text
~/.config/opencode/trans-genderian-orchestra/conductor_append.md
```

or for only the `github-copilot` preset:

```text
~/.config/opencode/trans-genderian-orchestra/github-copilot/conductor_append.md
```

Example content:

```markdown
## Local Conductor Preference

- Before spawning parallel writer agents, identify non-overlapping file ownership.
- If file ownership overlaps, ask the user or serialize the work.
```

### Replace a built-in prompt entirely

Create:

```text
~/.config/opencode/trans-genderian-orchestra/conductor.md
```

Use this rarely. Full replacements must restate all essential plugin behavior, because they replace the bundled prompt.

## Safe Improvement Rules

Configuration changes affect future agent behavior, so treat them as user-owned.

1. **Ask before changing config or prompts.**
   - Explain the proposed improvement briefly.
   - State which file would change.
   - Ask for confirmation unless the user explicitly requested the exact edit.
2. **Prefer narrow changes.**
   - Do not rewrite large prompts when a small rule solves the problem.
   - Do not add custom agents for one-off tasks.
3. **Preserve existing user settings.**
   - Merge with current config rather than regenerating from scratch.
   - Keep comments and formatting where practical for JSONC files.
4. **Avoid hidden behavior changes.**
   - Mention cost, permissions, or delegation changes before applying them.
   - Be explicit if a model/provider change may increase spend.
5. **Tell the user about restart requirements.**
   - OpenCode may need a restart for config, prompt, agent, skill, MCP, plugin, or shell environment changes to take effect.
   - Phrase it as: "This should apply on the next OpenCode run; restart OpenCode if you need it immediately."

## Configuration Workflow

When making or proposing changes:

1. **Inspect current setup**
   - Read the existing TGO config file.
   - Identify active `preset` and relevant agent blocks.
   - Check whether the user has local project `.opencode/` overrides.
2. **Decide the smallest useful change**
   - Model/preset tuning for performance, quality, or cost.
   - Prompt tuning for recurring behavior.
   - Custom agent when a repeatable specialty deserves a separate lane.
   - Skill/MCP permission change when access is too broad or too narrow.
3. **Ask for confirmation**
   - Show a concise proposal.
   - Include the target file path.
4. **Apply the edit carefully**
   - Preserve unrelated settings.
   - Prefer JSONC-compatible output if editing a JSONC file.
   - Keep agent names and skill/MCP names exact.
5. **Validate**
   - Ensure the file remains parseable.
   - Run available config checks if the repository provides them.
6. **Explain activation**
   - Tell the user whether the change applies immediately or on next OpenCode run/restart.

## Custom Agent Pattern

Custom agents work best when they are narrow, repeatable, and easy for the Conductor to route.

Use this shape as a starting point:

```jsonc
{
  "agents": {
    "api-reviewer": {
      "model": "github-copilot/claude-opus-4.7",
      "variant": "max",
      "prompt": "You review API design, compatibility, error semantics, and migration risk. Return concise findings with file references.",
      "conductorPrompt": "Delegate to @api-reviewer for API contract changes, public SDK changes, backwards-compatibility questions, or migration-risk review. Do not use it for routine implementation.",
      "skills": [],
      "mcps": []
    }
  }
}
```

Good custom agents have:

- a specific job;
- clear trigger conditions in `conductorPrompt`;
- explicit non-use conditions;
- only the skills and MCPs they actually need;
- a model appropriate to the task's judgment/cost needs.

Avoid custom agents that duplicate existing specialists:

- codebase scouting or external docs research → `scribe`
- implementation, docs editing, UI/UX, tests, bug fixes → `composer`
- architecture/debugging/final verification → `principal`
- multi-model consensus or review panel → `ensemble`

## Prompt Tuning Pattern

Prompt edits are best for recurring behavior that should happen across many sessions.

Good reasons to tune a prompt:

- The Conductor repeatedly delegates too much or too little for this user's workflow.
- A specialist repeatedly misses a project-specific convention.
- The user wants a stable communication or verification style.
- The team has a recurring review checklist or deployment rule.

Poor reasons to tune a prompt:

- A one-off task failed once.
- The current problem can be solved by normal instruction in this session.
- The change would make the agent worse for general use.

When suggesting a prompt improvement, say:

```text
I noticed this is recurring. I can add a small rule to <agent/config path> so future runs handle it automatically. Want me to make that config change?
```

## Examples

### Make Conductor more conservative with background writers

Proposal:

```text
I can add a narrow Conductor prompt rule to avoid parallel writer agents in the same directory unless their file ownership is explicit. Target: ~/.config/opencode/trans-genderian-orchestra/conductor_append.md. Apply it?
```

### Add a project-specific reviewer

Proposal:

```text
This looks repeatable enough for a custom read-only reviewer agent. I can add `api-reviewer` with no skills or MCPs and a `conductorPrompt` that routes public API changes to it. Apply to your TGO config?
```

### Warn about restart

After editing:

```text
Updated the config. This should apply on the next OpenCode run; restart OpenCode if you need it immediately.
```
