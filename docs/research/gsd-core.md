Not scoped out: this is the canonical GSD repo — no re-scope needed. It is a **meta-prompting / context-engineering / spec-driven-development framework** (not a runtime): it layers on top of Claude Code, OpenCode, Codex, Cursor, etc. One disclaimer: heavy, dogfooded (26k+ tests), and somewhat sprawling; TGO should copy *patterns*, not the surface area.

## (a) Core orchestration primitive

The **phase loop** is the central primitive: every unit of work (a *phase*) moves through `Discuss → (UI) → Plan → Execute → Verify → Ship`, repeating per milestone ([docs/explanation/the-phase-loop.md](https://github.com/open-gsd/gsd-core/blob/next/docs/explanation/the-phase-loop.md)). Control flow is **orchestrator-driven and prescriptive**, not a graph runtime or event bus:

- **Thin orchestrators** are Markdown workflow files (`gsd-core/workflows/*.md`, 89 shipped). The user invokes a command/skill; the workflow runs in the main session and loops: `gsd-tools.cjs init <workflow> <phase>` (load a compact JSON context payload) → `resolve-model <agent>` → spawn a specialized agent with a **fresh 200k-token context** → collect its result → update file-based state → next step ([ARCHITECTURE.md](https://github.com/open-gsd/gsd-core/blob/next/docs/ARCHITECTURE.md)). The orchestrator never does heavy lifting — it "does not write code and does not interpret results beyond routing them."
- **Completion markers as control flow.** Agents terminate by printing an H2 marker (e.g. `## PLANNING COMPLETE`, `## CHECKPOINT REACHED`, `## ISSUES FOUND`); the workflow regex-matches these to decide routing ([gsd-core/references/agent-contracts.md](https://github.com/open-gsd/gsd-core/blob/next/gsd-core/references/agent-contracts.md)). This is a deliberately low-tech but robust handshake.
- **Wave-based parallelism = a plan DAG.** Within `execute-phase`, `PLAN.md` files declare `depends_on`; the orchestrator groups them into dependency waves — independent plans run in parallel, dependent plans wait. Each executor commits atomically with `--no-verify`; the orchestrator runs pre-commit hooks once per wave and writes `STATE.md` under a lockfile.
- The loop is codified in a generated **Loop Host Contract**: 12 hook points (`discuss:pre/post`, `plan:pre/post`, `execute:pre/wave:pre/wave:post/post`, `verify:pre/post`, `ship:pre/post`), each declaring its `agentRoles` and `coreArtifacts` produces/consumes ([gsd-core/bin/lib/loop-host-contract.cjs](https://github.com/open-gsd/gsd-core/blob/next/gsd-core/bin/lib/loop-host-contract.cjs)).

## (b) Agent definition & delegation

- **Agents are Markdown + YAML frontmatter** — 33 files in `agents/*.md`, each declaring `name`, `description`, `tools` (whitelist: Read, Write, Edit, Bash, Grep, Glob, Skill, MCP tools…), and `color` for terminal output. Bodies are carefully engineered "meta-prompts" (role, execution flow, deviation rules, commit protocol, completion format). Large agents are decomposed into core + reference files read lazily to stay under runtime size limits.
- **Delegation is explicit and deterministic**, decided by the workflow, not emergent. Who acts next is pre-scripted per step: 4 parallel researchers → synthesizer → planner → plan-checker (≤3 revision loops) → parallel executors in waves → verifier → UAT (human) → ship. Agents are **reactive**: spawned by the orchestrator, run to completion, return a marker; they never volunteer work.
- **Human-in-the-loop via checkpoints**, not spontaneous questions: tasks can be `type="checkpoint:human-verify | decision | human-action"`; the executor stops and returns a structured `## CHECKPOINT REACHED` block (completed-tasks table, current task, exact blocker). A fresh *continuation* agent is spawned to resume with `<completed_tasks>` context ([agents/gsd-executor.md](https://github.com/open-gsd/gsd-core/blob/next/agents/gsd-executor.md)).
- **Autonomy is a mode, not the default**: `gsd-autonomous` chains `discuss → plan → execute` across all remaining phases, auto-approving checkpoints *except* package-legitimacy gates (`gate="blocking-human"`) ([skills/gsd-autonomous/SKILL.md](https://github.com/open-gsd/gsd-core/blob/next/skills/gsd-autonomous/SKILL.md)).

## (c) Context & shared-state passing

- **All shared state is files in `.planning/`** — human-readable Markdown/JSON, no database: `PROJECT.md`, `REQUIREMENTS.md`, `ROADMAP.md`, `STATE.md`, `config.json`, plus per-phase `phases/XX-name/` with `CONTEXT.md`, `RESEARCH.md`, `PLAN.md`(s), `SUMMARY.md`, `VERIFICATION.md`, `UI-SPEC.md`, `UAT.md`. "The next agent always starts from persisted, verified artifacts rather than from a reconstructed memory."
- **`STATE.md` is the spine**: records active milestone/phase, completed plans, decisions, blockers, progress. Every workflow reads it first to orient; every step writes back. This is what makes the loop survive context resets, `/clear`, and multi-day gaps.
- **Artifact routing is explicit**: a context-propagation table maps each artifact to its consumers (e.g. `CONTEXT.md` → researcher/planner/executor; `PLAN.md` → executor/plan-checker; `SUMMARY.md` → verifier). Each agent gets only what it needs (context isolation).
- **Parallel-write safety**: every `STATE.md` write uses an `O_EXCL` lockfile (`STATE.md.lock`, 10s stale timeout, spin+jitter).
- **Machine-readable decisions**: `CONTEXT.md` doubles as a **predicate fact-store** — single-line `CLASS.subkey=value` declarations that a CLI parses/selects, with a drift-guarded index. Verification checks *decision coverage* (did shipped code implement every declared decision?) and requirement coverage (REQ-IDs → plans).
- **Cross-phase defect memory**: a broken-windows ledger (`.planning/WINDOWS.md`) accumulates stubs/skipped-tests/unrun-verifies and **blocks `/gsd-ship`** while any entry is open.
- **Cross-session memory beyond files**: an optional **MemPalace** capability (MCP server + `recall`/`capture` skills, temporal knowledge graph) recalled before planning and captured at phase boundaries.

## (d) Roster philosophy

- Roles are organized as a **functional pipeline taxonomy** mirroring research → plan → execute → verify: Researchers, Synthesizers, Planners, Checkers, Executors, Verifiers, Mappers, Debuggers, Auditors, Doc-writers, Profilers — each with typical parallelism (4 parallel researchers; sequential verifiers) ([docs/explanation/multi-agent-orchestration.md](https://github.com/open-gsd/gsd-core/blob/next/docs/explanation/multi-agent-orchestration.md)).
- **Least privilege per agent**: each agent's frontmatter whitelists its exact tools. "An agent that only needs to read files and write a single output document gets exactly those permissions — no Bash." Small blast radius if an agent misbehaves.
- **Model tiering as part of the roster**: every agent has a `quality | balanced | budget | adaptive | inherit` model-profile column, plus a default tier (`light/standard/heavy`). Rationale is explicit: *planning and debugging* get the strongest model (reasoning has highest impact there); *executors* follow explicit plans (Sonnet); *mappers/checkers* are cheap (Haiku) — high-volume structured output ([gsd-core/references/model-profiles.md](https://github.com/open-gsd/gsd-core/blob/next/gsd-core/references/model-profiles.md)). A phase-type map lets you tier at the phase level without learning agent names. **Dynamic routing** escalates a cheap tier to the next up on orchestrator-detected soft failure.
- Colors per agent are for terminal legibility; roles are discoverable from a single `agents/` dir.

## (e) Skills & tools shipped

- **~67 skills / slash-commands** across 6 namespaces (`gsd-workflow`, `gsd-project`, `gsd-quality`, `gsd-context`, `gsd-manage`, `gsd-ideate`). Namespace **meta-skills** layer above concrete skills purely to cut the eager skill-listing token cost (~120 tokens for 6 routers vs ~2,150 flat; "Tool Attention" research: keyword-dense descriptions route better at ~40% the tokens) ([docs/COMMANDS.md](https://github.com/open-gsd/gsd-core/blob/next/docs/COMMANDS.md)).
- **`gsd-tools.cjs` CLI** (Node, CJS): a Command Routing Hub with a no-throw pure-result contract (`{ok, kind, payload}`). Families include `config`, `state`, `phase`, `roadmap`, `milestone`, `verify`, `template`, `frontmatter`, `init` (context payloads), `model-resolver`, `uat`, `workstream`, `intel` (codebase intelligence), `graphify`, `audit`, `estimate-calibration`, `windows` (broken-windows ledger), `context-predicates`. gsd-tools is the *only* hard dependency of agents — the whole system needs nothing beyond `node`.
- **MCP servers, used sparingly**: `gsd-mcp-server` exposes just 3 JSON-RPC tools (`gsd_command`, `gsd_read_state`, `gsd_write_state`) so any host can drive GSD. Docs lookup uses Context7 MCP (with a `ctx7` CLI fallback via Bash — "Do not skip documentation lookups because MCP tools are unavailable"). The docs warn that heavyweight MCP servers cost **20k+ tokens/turn** and should be enabled surgically. MemPalace memory ships its own MCP server.
- **Research module** (fetch-to-disk): content-addressed cache + provider waterfall (`Context7→Ref→Jina→websearch` for docs; `Exa→Tavily→Perplexity→Brave→websearch` for web; `Firecrawl→Jina` for scrape), confidence stamping, and a package-legitimacy verdict (`OK|SUS|SLOP`) to catch slopsquatted deps. Agents always return a `RESEARCH.md` path, never raw fetched content.
- **Runtime hooks**: `statusline`, `context-monitor` (warns at 35%/25% headroom), `prompt-guard` / `read-injection-scanner` (prompt-injection defense), `read-guard`, `workflow-guard`, `check-update`, `phase-boundary`, `validate-commit` (conventional commits). Also **gate system** — 4 canonical gate types (Confirm, Quality, Safety, Transition) wired into plan-checker and verifier.
- **Human-in-the-loop surfaces**: `UAT.md` as a required final human gate; checkpoints; `gsd-browser` companion for deterministic Chrome verification with visual evidence (assertions, recordings, traces, human takeover).
- **Capability overlay system**: opt-in features (memoriale, intel, claude-orchestration, ai-integration…) as manifests with consent gates + confinement, installable per project.

## (f) Steal-worthy bits

1. **Completion-marker agent contracts** (`## PLANNING COMPLETE` / `## CHECKPOINT REACHED`, regex-matched by the workflow) — a zero-dependency handshake that lets an orchestrator deterministically know when a spawned agent finished and how to route, so a chain of agents can run autonomously with no slash commands and no event bus.
2. **File-backed `STATE.md` as the orchestration substrate, guarded by an `O_EXCL` lockfile** — durable "where are we now" navigation passed between agents as plain Markdown, safe under parallel writes; this is the whole answer to cross-agent context passing, and it lets an autonomous loop resume anywhere after a crash or context reset.
3. **Structured checkpoint protocol** (`human-verify | decision | human-action`, `gate="blocking-human"` carve-outs, `## CHECKPOINT REACHED` return format with a completed-tasks table) — the mechanism that makes agentic autonomy safe: it converts every judgment call into an explicit, resumable pause instead of a silent assumption, while still letting auto-mode push through routine work.
4. **Least-privilege named roster in Markdown frontmatter** (`name/description/tools/color`) + per-role model tiering (strong for planning, cheap for mapping) — a named, discoverable, tool-whitelisted cast of agents with built-in cost discipline, which is exactly TGO's "named roster" goal and a concrete "skills-over-MCPs" stance (whitelist tools per role; reach for a CLI fallback before a heavyweight MCP server that costs 20k tokens/turn).
5. *(Bonus for "concise writing")* **Byte-budget ceilings + progressive disclosure on workflow files** — every orchestrator is capped (38k/54k/90k bytes by tier) and fattens only by lazy `Read` of extracted step/template/reference files, because "leaner, higher-signal instructions produce better plans." Workflows are held to size tests with a tighten-only ratchet. This is the direct implementation of concise writing as a mechanism.
