## (a) Core orchestration primitive

**LangGraph** is a low-level, code-driven state-machine runtime (MIT, "inspired by Google's Pregel and Apache Beam"; API modeled on NetworkX). The central abstraction is a `StateGraph`: a graph of **nodes** (plain Python functions that do work) and **edges** (fixed edges, or conditional edge functions that pick the next node from current state), all reading/writing one shared, typed **State** object. "Nodes do the work, edges tell what to do next." Execution is message-passing in discrete "super-steps" (Pregel): a node activates when it receives state on an incoming channel, runs, and posts updates; parallel nodes share a super-step; the run terminates when no messages are in transit. Control flow is expressed in **code** (functions + `add_node`/`add_edge`/`add_conditional_edges`/`Command`), then `.compile()`d (compile just validates and wires checkpointers/breakpoints). A recursion limit (default 1000 super-steps) caps runaway loops. Its core value is mixing deterministic, hand-coded steps with LLM-driven agentic steps in the same graph.

**Deep Agents** is a higher-level "agent harness" that layers *on top of* LangGraph. Its primitive is a single opinionated coordinator loop with bundled middleware: filesystem, subagents, skills/memory, summarization/offloading, HITL, and (opt-in) a `write_todos` planning tool. Control is still a LangGraph graph, but the harness pre-wires the loop so you just pass `create_deep_agent(model=..., tools=..., system_prompt=...)`. The stack is: LangChain (framework: abstractions/integrations) → LangGraph (runtime: durable execution, streaming, HITL, persistence) → Deep Agents (harness: predefined tools, prompts, subagents).

Anthropic's system uses the same shape without a graph runtime: a lead agent that plans and spawns subagents, iterating until synthesis is done — control is emergent, carried entirely by prompts + tools rather than explicit edges.

## (b) Agent definition & delegation

**LangGraph**: agents are defined **in code** — a node is any function (may call an LLM, a tool, or pure logic); edges (conditional functions) decide which node runs next. There is no declarative agent roster. Delegation is structural: a node can `Send` work to a downstream node, or a subgraph (a compiled graph used as a node) handles nested orchestration. The LLM participates only where a node routes on an LLM decision; otherwise routing is deterministic code. `Command` combines a state update with a `goto` target in one return, and `Command(graph=Command.PARENT)` lets a subgraph node navigate the parent graph (used for multi-agent handoffs).

**Deep Agents**: the coordinator (main agent) delegates **emergently** through a built-in `task` tool — the LLM picks a subagent by name from tool schemas. Each subagent is ephemeral: fresh context, runs autonomously to completion, returns exactly **one final report/handoff** to the coordinator, then dies. Subagents are declared as dicts (`name`, `description`, `system_prompt`, `tools`, `model`, `middleware`, `skills`, `response_format`, `permissions`) or as `CompiledSubAgent` (any prebuilt LangGraph graph — "any LangGraph CompiledStateGraph can be passed in as a sub-agent"). A default `general-purpose` subagent exists unless overridden; delegation is driven by each subagent's `description` (the docs: the main agent "uses this to decide when to delegate"). **Dynamic subagents** (beta): with a QuickJS interpreter attached, the agent can dispatch subagents *from code* — loops/branches/parallel batches calling a `task()` global — i.e. the agent writes its own orchestration. The trigger is a prompt heuristic: phrasing a request as a "workflow" opts into code-driven fan-out.

Anthropic's pattern: an **orchestrator-worker** structure — a `LeadResearcher` decomposes the query, spawns 3–5 parallel subagents (each with an objective, output format, tool/source guidance, and explicit task boundaries), waits, synthesizes, and respawns until done, then a dedicated CitationAgent post-processes. Key prompt lesson: "teach the orchestrator how to delegate" — vague subagent briefs cause duplicated/gapped work.

## (c) Context & shared-state passing

**LangGraph**: all nodes share one **State** object; each state key is a "channel" with a **reducer** that defines how node updates fold in (default: overwrite; `operator.add` for accumulation; `add_messages` for message lists with ID-aware merging; arbitrary custom reducers). Nodes see the accumulated state and emit partial updates. Two persistence layers: **checkpointers** (thread-scoped snapshots of graph state — short-term memory, resume-after-failure, "time travel", HITL) and **stores** (cross-thread, namespaced key/value JSON — long-term memory like user facts/preferences). A `thread_id` in config is the persistent cursor. Subgraphs have separate checkpoint namespaces — the docs explicitly warn that parent state updates from a subgraph may not be visible immediately; use a store for cross-boundary data.

**Deep Agents** manages context aggressively. Filesystem is the shared substrate (see §e). Mechanisms: **(1) Offloading** — tool-call inputs/results over ~20k tokens are written to the filesystem and replaced in-context with a file reference (+10-line preview); **(2) Summarization** — `SummarizationMiddleware` triggers at ~85% of the model's context window, LLM-generates a structured summary (session intent, artifacts, next steps) that replaces history while a text rendering is preserved on disk; keeps ~10% recent tokens; an opt-in `compact_conversation` tool lets the agent compact on demand; **(3) Isolation** — subagents quarantine heavy subtask context so the coordinator only ever sees the final report; **(4) Memory** — `AGENTS.md` files are *always* loaded (memory), while skills are loaded progressively (frontmatter at startup, full body on demand); **(5) Prompt caching** — static system-prompt sections (base prompt, memory, skills) are auto-cache-eligible on Anthropic/Bedrock. Runtime context (user ids, keys) propagates to all subagents; long-term memory is a `CompositeBackend` routing `/memories/` to a LangGraph Store.

Anthropic: subagents are themselves "compression" — "the essence of search is compression"; parallel context windows condense findings before the lead sees them. Also: persist the plan to external memory so it survives context truncation; and the **subagent-writes-to-filesystem pattern** — subagents store artifacts in external storage and return lightweight references, minimizing "the game of telephone" and token overhead of copying large outputs through the coordinator.

## (d) Roster philosophy

**LangGraph**: no roster — you design the graph. There is no notion of named agent identities beyond node names.

**Deep Agents**: small, **named**, mostly **fixed** roster. Exactly one coordinator ("main agent", identifiable by `name=`) plus subagents the coordinator can spawn. Default is one `general-purpose` subagent (filesystem tools, inherits main agent's skills); you add a handful of named specialists (`research-agent`, `reviewer`, etc.). Spawning is dynamic (any number of ephemeral instances of the fixed types at runtime, via `task` or via interpreter-driven dynamic subagents) but the *types* are declared up front. Subagent names are first-class: they tag `AIMessage`s and streams (`stream.subagents` gives per-subagent handles) and appear as `lc_agent_name` metadata for tracing/filtering. The philosophy: **one generalist coordinator + a small set of named specialists**, rather than many generalists or auto-generated identities.

Anthropic: same — one lead + a few specialized subagents, all named by role (LeadResearcher, Subagent, CitationAgent), with an effort-scaling heuristic (1 agent for simple fact-finding, 2–4 subagents for comparisons, 10+ for complex research). Explicit guidance in §a–c: subagent outputs should be concise summaries, not raw data — a direct nod to TGO's concise-writing goal.

## (e) Skills & tools shipped

LangGraph itself ships no skills/tools — only orchestration primitives (interrupts, streaming, memory). Deep Agents is where the tool surface lives:

- **Virtual filesystem tools**: `ls`, `read_file` (line numbers, offset/limit, multimodal returns for images/video/audio/PDF), `write_file`, `edit_file` (exact string replacement), `delete`, `glob`, `grep`, and `execute` (shell, sandbox backends only). Backends are pluggable: in-memory state, local disk, LangGraph Store, `CompositeBackend` (path-routed), or custom; declarative permission rules (`operations`, `paths` globs, `mode` allow/deny, first-match-wins, applied per subagent too).
- **MCP**: full Model Context Protocol support — pass tools from any MCP server alongside plain functions/LangChain tools.
- **Code execution**: sandbox backends (`execute`) and a QuickJS interpreter (`eval`), the latter enabling dynamic subagents.
- **Skills**: Agent Skills standard (https://agentskills.io), `SKILL.md` + scripts/templates/refs, progressive disclosure, per-subagent skill sets.
- **Memory**: `AGENTS.md` loaded at startup, updatable by the agent ("improve over time").
- **Human-in-the-loop**: LangGraph `interrupt()` — pause inside any node *or inside a tool*, payload surfaced to caller, resume with `Command(resume=...)`; Deep Agents exposes `interrupt_on={"edit_file": True}` to gate specific tools. Static compile-time/runtime breakpoints also exist for debugging.
- **Planning (opt-in)**: `TodoListMiddleware` gives a `write_todos` tool (pending/in_progress/completed) persisted in state.
- **Streaming**: typed projections (`stream.messages`, `stream.values`, `stream.interrupts`, `stream.subagents`) with token-level streaming.

## (f) Steal-worthy bits

1. **Filesystem-as-shared-memory + offload** (Deep Agents/Anthropic). The harness persists large artifacts (tool results, subagent reports, memories) as files and passes references, not payloads — the cheapest way to keep a single coordinator's context clean across long autonomous runs; directly serves TGO's agentic autonomy and skills-over-MCPs goals (file ops become the substrate, not an MCP integration).
2. **Ephemeral named subagents with single handoff** (Deep Agents/Anthropic). `task`-tool delegation to a small declared roster (named, described, per-agent tools/model/skills), each returning one concise report — this is a ready-made shape for TGO's "named roster" and "no slash commands": the coordinator is steered by prompt, not by commands, and subagent identities give streaming/tracing affordances.
3. **Progressive-disclosure skills + always-on memory** (Deep Agents). Skills expose only `SKILL.md` frontmatter at startup and load bodies on demand; memory (`AGENTS.md`) is always loaded — exactly the skills-over-MCPs model TGO wants, and it keeps startup context compact so the system prompt stays lean (concise writing).
4. **Summarization + on-demand compaction at a token threshold** (Deep Agents). Auto-condense history into an intent/artifacts/next-steps summary at ~85% of context, keep the last ~10%, and let the agent call `compact_conversation` itself between tasks — the concrete mechanism that lets a single autonomous agent run indefinitely without manual context management, and a good fit for TGO's concise-output bias.
